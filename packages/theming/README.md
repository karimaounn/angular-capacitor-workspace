# @angular-capacitor-workspace/theming

Theme switching for workspaces generated by
[`angular-capacitor-workspace`](https://www.npmjs.com/package/angular-capacitor-workspace):
a colour scheme (system, light or dark) and a palette, as signals, written onto
`<html>` and remembered.

You do not install or wire this yourself. `npm create
angular-capacitor-workspace` with `--ui-lib`, or
`ng generate angular-capacitor-workspace:theming`, adds it to a workspace, binds
it to the design system's `src/config/palettes.ts`, re-exports it from the
design system, and puts `provideTheme()` in each app. An update of this package
updates how theming works in every workspace that has it; the palettes stay in
the config.

## How it works

Two attributes on `<html>`: `data-theme` for the mode and `data-palette` for the
palette. The design system's stylesheet declares every combination, so a switch
is an attribute write — nothing re-renders. `system` removes `data-theme`, so
`prefers-color-scheme` in the stylesheet governs and the page follows the OS
live.

## What it provides

- `provideTheme({ palettes, storagePrefix, defaultPalette? })` — the providers.
  A design system wraps it as `provideTheme()`.
- `ThemeService` — `mode`, `palette` and `resolvedMode` as signals, and `next()`
  to cycle the mode.
- `themeStorageKeys(prefix)` — the `localStorage` keys, which the generated
  script that applies the choice before the first paint reads too.
- `Register` — the interface a workspace augments with its palettes, which makes
  `PaletteId` their union.

Peers `@angular/core` and `@angular/common` at the same major as this package.
