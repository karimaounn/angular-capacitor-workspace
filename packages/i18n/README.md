# @angular-capacitor-workspace/i18n

Runtime translation for workspaces generated by
[`@angular-capacitor-workspace/cli`](https://www.npmjs.com/package/@angular-capacitor-workspace/cli):
every locale in one build, switched without a reload, with writing direction and
plurals from `Intl`.

You do not install or wire this yourself. `--i18n` on
`npm create @angular-capacitor-workspace`, or
`ng generate @angular-capacitor-workspace/cli:i18n`, adds it to a workspace, binds it
to the design system's `src/config/i18n.ts`, and re-exports it from the design
system, so applications import `TranslationService`, the `t` pipe and
`provideTranslations` from there. An update of this package updates how
translation works in every workspace that has it; the locales stay in the
config.

## Why runtime

Compile-time i18n (`@angular/localize`) emits one bundle per locale. An app
shipped inside a Capacitor shell has one `webDir` with one `index.html`, so that
would mean one binary per language. Here every locale is in one build.

## What it provides

- `provideI18n(config, loader, { storageKey, locale? })` — the providers. A
  design system wraps it as `provideTranslations(loader)`.
- `TranslationService` — the active locale and direction as signals, lookups
  with `{placeholder}` interpolation, plurals from `Intl.PluralRules`, and
  `formatNumber` / `formatDate` / `formatRelativeTime` that follow a runtime
  switch, which Angular's pipes do not.
- `TranslatePipe` — `{{ 'cart.items' | t: { count } }}`.
- `localeTables(config)` — `LOCALES`, `DEFAULT_LOCALE`, the direction and label
  tables, and BCP-47 matching, typed by the config.
- `Register` — the interface a workspace augments with its config, which makes
  `Locale` the union of its locales:

  ```ts
  declare module "@angular-capacitor-workspace/i18n" {
    interface Register {
      i18n: typeof I18N;
    }
  }
  ```

Peers `@angular/core` and `@angular/common` at the same major as this package.
