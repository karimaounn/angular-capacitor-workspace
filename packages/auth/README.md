# @angular-capacitor-workspace/auth

Sign-in for workspaces generated by
[`@angular-capacitor-workspace/cli`](https://www.npmjs.com/package/@angular-capacitor-workspace/cli):
a session, route guards and an HTTP interceptor that work the same with every
identity provider, and Amazon Cognito as the first.

You do not install or wire this yourself. `npm create
@angular-capacitor-workspace` with `--auth cognito`, or
`ng generate @angular-capacitor-workspace/cli:auth`, adds it to a workspace,
binds it to the design system's `src/config/auth.ts`, re-exports it from the
design system, and gives each app sign-in screens and
`provideAuthentication(…)`. An update of this package updates how sign-in works
in every workspace that has it; the settings stay in the config.

## How it is split

The provider-neutral half is the package's main entry point. Screens and apps
are written against it alone:

- `AuthSession` — the session as signals (`isAuthenticated`, `idClaims`,
  `expiresAt`), `validate()`, which refreshes an expired access token first,
  and the tokens.
- `PasswordAuthService` — email and password: sign-in, the new-password
  challenge, registration, recovery and change.
- `AccountService` — attributes, sign-out everywhere, account deletion.
- `authGuard`, `guestGuard` and `authInterceptor`, which sends the token to
  `apiBaseUrl` and nowhere else.
- `AuthError`, whose `code` screens branch on, and `AuthAction`, a form's busy
  and error state.

The provider's half is a backend from another entry point, passed to
`provideAuth`:

```ts
import { provideAuth } from "@angular-capacitor-workspace/auth";
import { withCognito } from "@angular-capacitor-workspace/auth/cognito";

provideAuth(
  { routes: { signIn: "/auth/sign-in", afterSignIn: "/" }, apiBaseUrl: "https://api.example.com" },
  withCognito({ userPoolId: "us-east-1_AbC123xYz", userPoolClientId: "…" }),
);
```

A backend implements the session and whichever sign-in methods its provider
offers. One without passwords leaves them out, and `PasswordAuthService` fails
with `NotSupported`. The contract between the two halves (`SESSION_BACKEND` and
the others) is for this package's own backends and can change in any minor; the
services in front of it follow semver.

## Cognito

`@angular-capacitor-workspace/auth/cognito` signs in over SRP, so the password
never leaves the browser, through `amazon-cognito-identity-js`. That is an
optional peer: a workspace that signs in with Cognito installs it, and one that
does not never downloads it.

The SDK is loaded while the app starts, with `import()`, rather than when the
entry point is imported: a design system that binds the backend is imported by
pages that never sign anyone in, and they do not load it. The SDK depends on
`buffer@4`, which reads Node's `global`; the entry point defines it, if the page
has none, just before loading the SDK.

An app whose pool is not set yet starts signed out, and every sign-in call fails
with `NotConfigured`, saying what to set. `cognito(settings)` returns its
argument, typed as `CognitoConfig`: a workspace's environment names its pool as
`auth: cognito({ … })`, so a missing or misspelt field fails the build on that
line rather than where the environment is handed to the provider.

Peers `@angular/core`, `@angular/common` and `@angular/router` at the same major
as this package, and `rxjs` 7.
